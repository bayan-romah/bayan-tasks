# استضافة نظام بيان داخل المملكة

دليل تشغيل النظام على خادم سعودي، حين يُلزِم الالتزام النظامي ببقاء بيانات الموظفين داخل المملكة.

---

## لماذا هذا المسار

Supabase السحابي لا يملك منطقة سعودية. لكنه **مفتوح المصدر** ويعرض نفس الواجهة البرمجية حين يُستضاف ذاتياً — فلا يتغيّر سطر واحد في كود النظام: نفس سياسات RLS، ونفس دالة `task_action`، ونفس المصادقة والمرفقات. يتغيّر **رابط واحد** في `js/config.js`.

## ما ستحصل عليه

```
النطاق ── Cloudflare DNS فقط (سحابة رمادية، بلا بروكسي)
            ↓
   خادم داخل السعودية
   ├── Caddy      شهادة TLS تلقائية ومتجددة
   ├── /          واجهة النظام (ملفات ثابتة)
   ├── /rest /auth /storage    ← Supabase
   └── /studio    لوحة إدارة قاعدة البيانات
            ↓
   نسخ احتياطي يومي → تخزين داخل المملكة
```

**لا يمرّ أي شيء عبر خادم خارجي.** حتى Cloudflare يُستخدم لتحويل الأسماء فقط (DNS) لا لتمرير البيانات — لذلك السحابة **رمادية** لا برتقالية.

## ١. اختيار المزوّد

اشترط منطقة داخل المملكة (الرياض / الدمام / جدة). خيارات لها مناطق سعودية:

| المزوّد | المنطقة |
|---|---|
| Google Cloud | الدمام `me-central2` |
| Oracle Cloud | جدة `me-jeddah-1` |
| Alibaba Cloud (SCCC) | الرياض |
| Huawei Cloud | الرياض |
| مزوّدون محليون | STC Cloud · SITE · وغيرهم |

> تحقّق من المنطقة بنفسك عند الشراء — لا تفترضها.

**المواصفات المطلوبة:**

| | الحد الأدنى | الموصى به |
|---|---|---|
| المعالج | 2 vCPU | 4 vCPU |
| الذاكرة | 4 GB | 8 GB |
| القرص | 40 GB SSD | 80 GB SSD |
| النظام | Ubuntu 22.04 أو 24.04 | |

Supabase المستضاف ذاتياً يشغّل نحو 10 حاويات؛ أقل من 4 جيجابايت ذاكرة يتعثّر.

## ٢. تجهيز الخادم — أمر واحد

بعد إنشاء الخادم وتوجيه النطاق إليه (سجل `A` يشير لعنوان الخادم، **سحابة رمادية**):

```bash
scp -r selfhost/ root@<عنوان-الخادم>:/root/
ssh root@<عنوان-الخادم>
sudo bash /root/selfhost/setup.sh tasks.example.sa it@example.sa
```

السكربت يتولّى: تثبيت Docker · جلب Supabase · **توليد كل الأسرار عشوائياً** (كلمة مرور القاعدة، `JWT_SECRET`، ومفتاحَي `anon` و `service_role` موقّعين) · إعداد Caddy وشهادة TLS · ضبط جدار الحماية · تشغيل كل شيء.

ينتهي بملف `/opt/bayan/بيانات-الدخول.txt` فيه كل المفاتيح.

> ⚠️ **انسخه لمكان آمن خارج الخادم فوراً، ثم احذفه:**
> `shred -u /opt/bayan/بيانات-الدخول.txt`

## ٣. رفع النظام وتهيئة القاعدة

**أ) ارفع ملفات الواجهة:**
```bash
scp -r index.html assets js robots.txt root@<الخادم>:/opt/bayan/web/
```

**ب) شغّل السكربتين** من `https://<نطاقك>/studio` ← SQL Editor:
1. كامل محتوى `supabase/schema.sql`
2. ثم `supabase/seed.sql`

**ج) اربط الواجهة بالقاعدة** — عدّل `/opt/bayan/web/js/config.js`:
```js
SUPABASE_URL: "https://tasks.example.sa",
SUPABASE_ANON_KEY: "<ANON_KEY من ملف بيانات الدخول>",
```

**د) أنشئ حسابك كمالك:** افتح الموقع ← «حساب جديد» ← سجّل. ثم من Studio ← SQL Editor:
```sql
update public.profiles
set role = 'owner', active = true, job_title = 'الرئيس التنفيذي'
where email = 'بريدك@هنا';
```

## ٤. النسخ الاحتياطي — لا تؤجّلها

```bash
bash /root/selfhost/backup.sh --install
```

نسخة يومية 2:30 فجراً، تحتفظ بـ30 يوماً، وتفشل بصوت عالٍ إن كانت النسخة مريبة الصِغر.

**لكنها على نفس الخادم — وهذا لا يحميك من فقده.** أضف نسخاً خارج الخادم إلى تخزين داخل المملكة (التفاصيل في نهاية `backup.sh`).

**اختبر الاسترجاع فعلياً كل ثلاثة أشهر:**
```bash
bash backup.sh --restore /opt/bayan/backups/bayan_<تاريخ>.sql.gz
```
نسخة لم تُختبر ليست نسخة احتياطية.

---

## ٥. أغلق لوحة القاعدة بعد الإعداد

`/studio` تعطي صلاحية كاملة على البيانات. بعد انتهاء التهيئة، احذف مقطع `handle /studio*` من `/opt/bayan/caddy/Caddyfile` ثم:
```bash
cd /opt/bayan && docker compose -f docker-compose.caddy.yml restart
```
وحين تحتاجها لاحقاً، افتحها عبر نفق SSH بدل تعريضها للإنترنت:
```bash
ssh -L 8000:localhost:8000 root@<الخادم>
# ثم افتح http://localhost:8000 على جهازك
```

## ٦. المسؤوليات المستمرة — اقرأها قبل الالتزام

الاستضافة الذاتية تنقل هذه المهام إليكم:

| المهمة | التكرار | الأمر |
|---|---|---|
| تحديثات أمنية للنظام | شهرياً | `apt update && apt upgrade -y` |
| تحديث حاويات Supabase | ربع سنوي | `cd /opt/bayan/supabase && docker compose pull && docker compose up -d` |
| التحقق من نجاح النسخ | أسبوعياً | `tail -20 /opt/bayan/backup.log` |
| اختبار الاسترجاع | ربع سنوي | `backup.sh --restore` على خادم تجريبي |
| مراقبة مساحة القرص | شهرياً | `df -h` |

**هذه ليست اختيارية.** إن لم يكن في الجمعية من يتولّاها، فاعقدوا عقد صيانة مع مزوّد محلي — تكلفته أقل بكثير من فقد بيانات أو اختراق.

## استكشاف الأعطال

**الموقع لا يفتح / لا شهادة:**
```bash
docker logs bayan-caddy --tail 50
```
غالباً السبب: النطاق لا يشير للخادم بعد، أو **السحابة برتقالية في Cloudflare** (يجب أن تكون رمادية ليصدر Caddy الشهادة).

**تسجيل الدخول لا يعمل:**
```bash
cd /opt/bayan/supabase && docker compose logs auth --tail 50
```
تحقّق أن `SITE_URL` و `API_EXTERNAL_URL` في `.env` تطابق نطاقك بالضبط مع `https://`.

**الخدمات لا تعمل:**
```bash
cd /opt/bayan/supabase && docker compose ps
docker compose logs --tail 100
free -h    # ذاكرة ممتلئة؟ تحتاج ترقية الخادم
```
